# Codex collaboration parity

This ledger tracks every known Codex collaboration parity surface, including matches, intentional differences, unsupported behavior, and unknowns. The reference is OpenAI Codex commit [`12933b69551394328319dcdd1bcee7907326dc85`](https://github.com/openai/codex/tree/12933b69551394328319dcdd1bcee7907326dc85). Status values are `match`, `partial`, `different`, `unsupported`, and `unknown`.

The provider transports Codex Responses requests; this extension owns Pi child sessions and the collaboration control plane. `multi_agent_version` is authoritative remote catalog data projected privately to Pi models as `multiAgentVersion`, not a standard Pi capability.

The compatibility goal is to minimize distribution shift for models trained and tuned in the native Codex harness. Matching the pinned implementation is the default for every portable model-facing surface these packages own. A non-match must identify a backend reservation, unavailable Pi capability or representation, safety/correctness requirement, or other concrete host constraint; it should be revisited when that constraint changes.

The [Codex model-facing contract](codex-model-facing-contract.md) and [implementation reference](codex-reference.md) are descriptive upstream references. Pi's normative behavior is defined in [protocols](protocols.md).

## Maintenance

Regenerate and verify the pinned fixture with:

```bash
pnpm --filter @clanker-stuff/subagents exec node scripts/extract-codex-contracts.ts --write
pnpm --filter @clanker-stuff/subagents exec node scripts/extract-codex-contracts.ts --check
```

Update every affected row when Codex, Pi, the provider, or the subagent implementation changes. A difference stays listed even when intentional or impossible to remove.

The extractor reads catalog declarations, native namespace names, namespace member names, name-ascending namespace merge order, and V2 spawn defaults directly from the pinned commit with `git show`; the checkout may be on another branch. It writes the typed generated fixture at `docs/fixtures/codex-contract.generated.ts`, and `--check` compares that artifact exactly. Unit tests compare the provider fallback declarations and namespace ordering plus the supported Pi tool families and stock V2 spawn surface/output against it, while preserving Pi's documented non-reserved namespace. This does not prove the rest of the manually reviewed model-facing reference.

The optional live model-guidance eval covers explicit non-delegation, proactive parallelism, queue-only addressing, and sparse waiting:

```bash
pnpm --filter @clanker-stuff/subagents exec node scripts/evaluate-model-guidance.ts --dry-run
pnpm --filter @clanker-stuff/subagents exec node scripts/evaluate-model-guidance.ts
```
