# Codex collaboration parity

This ledger tracks every known Codex collaboration parity surface, including matches, intentional differences, unsupported behavior, and unknowns. The reference is OpenAI Codex commit [`389dd5645944891b65e4ca584125bbb0c852d352`](https://github.com/openai/codex/tree/389dd5645944891b65e4ca584125bbb0c852d352). Status values are `match`, `partial`, `different`, `unsupported`, and `unknown`.

Selected tool facts remain pinned to `36f0dbe796d9bb1a18a0fc0640ed08b3e1d54564`. The generated fixture's [catalog declarations](https://github.com/openai/codex/blob/b412ff32c417f855c2b2d1581b77058eed87c84b/codex-rs/models-manager/models.json) advance separately to `rust-v0.156.1` (`b412ff32c417f855c2b2d1581b77058eed87c84b`), adding GPT-6 Sol and Luna as V2. The four previous declarations are unchanged. The September 13 review remains in Git history; rows below retain the September 2 behavior baseline unless explicitly annotated.

The latest stable [`rust-v0.158.0`, `064c6b8c737f5b41d171fdda80bd9ef10ad06eb3`](https://github.com/openai/codex/releases/tag/rust-v0.158.0) was checked on 2026-09-28 against the September 2 tool/control baseline and the divergent 0.156.1 catalog. Its stock V1/V2 tool names, required fields, output properties, and selected catalog collaboration declarations remain represented by the existing fixture. The default V2 spawn description dropped one instruction already absent from Pi's host-specific description. Native model-catalog description overrides and the opt-in `disable_direct_message`/message-board mode do not change Pi's stock tools; child-control refactors preserve the supported queue, follow-up, list, interrupt, and spawn results. This review does not repin historical contract prose, copied-source `UPSTREAM`, or the fixture without a corresponding adapted change.

The latest stable [`rust-v0.159.0`, `687a119f0fcaace47e1f1abcc77cec6c813fd6da`](https://github.com/openai/codex/releases/tag/rust-v0.159.0) was checked on 2026-09-29. The complete 605-path 0.158.0/0.159.0 tree difference and 5,374-path difference from the September 2 behavior baseline were inventoried. The stock collaboration specification and model-facing tool planner, names, required fields and result properties have no new change from 0.158.0; Astra/Sol/Luna still declare V2 in the divergent catalog. New opt-in `instant_interrupt` steers model generation and long-running Code Mode executions, but Pi's existing mail and cancellation boundaries do not advertise that capability. There is no adapted tool contract requiring fixture or copied-source repinning.

Dated deltas appear in the affected rows. The review also records new forked configuration/Guardian state and delegated-attribution behavior beyond Pi's application boundary. The fixture does not establish full current parity for these surfaces.

Native Pi owns inference, catalogs, compaction, and Code Mode; this extension owns child sessions and collaboration. Provider-catalog, Fast/service-tier inheritance, and provider-owned Ultra claims in the historical rows below describe the retired implementation, not current guarantees. The [native baseline](../../../../../docs/native-pi.md) and [protocols](protocols.md) govern current behavior. Native OpenAI models fall back to V1 unless V2 is explicitly configured; there is no private catalog projection or provider contract bridge.

The compatibility goal is to minimize distribution shift for models trained and tuned in the native Codex harness. Matching the pinned implementation is the default for every portable model-facing surface these packages own. A non-match must identify a backend reservation, unavailable Pi capability or representation, safety/correctness requirement, or other concrete host constraint; it should be revisited when that constraint changes.

Pi owns provider behavior and native Code Mode execution; collaboration schemas remain owned by this extension. V1 tools use Pi namespaces and `structuredContent`; V2 tools are model-only. There is no executable collaboration inventory outside Pi's registry.

The [Codex model-facing contract](codex-model-facing-contract.md) and [implementation reference](codex-reference.md) are descriptive upstream references. Pi's normative behavior is defined in [protocols](protocols.md).

Selected spawn-model guidance and validation were reviewed at [`af1fc2dbff641e78298c272c4b45c9fec5c33898`](https://github.com/openai/codex/tree/af1fc2dbff641e78298c272c4b45c9fec5c33898). This does not repin the historical contract fixture or imply a full upstream review.

## Provider placement and Code Mode

Provider authentication, catalogs, requests, transport, compaction, and Code Mode are owned by Pi's built-ins. The retired provider's wire and execution parity claims are not contracts of this extension.

V1 tools declare Pi namespaces, output schemas, and `structuredContent`. Native Code Mode calls them through Pi's nested tool pipeline, including permissions, lifecycle events, and persisted accounting. V2 tools are model-only and are not callable from scripts. Declaration visibility and execution capabilities follow native Pi configuration; there is no executable collaboration inventory outside Pi's registry.

## Maintenance

Regenerate and verify the pinned fixture with:

```bash
pnpm --filter @clanker-stuff/subagents exec node scripts/extract-codex-contracts.ts --write
pnpm --filter @clanker-stuff/subagents exec node scripts/extract-codex-contracts.ts --check
```

Update every affected row when Codex, Pi, the provider, or the subagent implementation changes. A difference stays listed even when intentional or impossible to remove.

The extractor records separate tool (`36f0db...`) and catalog (`b412ff...`) revisions and reads catalog declarations, native namespace names, namespace member names, name-ascending namespace merge order, and V2 spawn defaults directly from those pinned commits with `git show`; the checkout may be on another branch. It writes the typed generated fixture at `docs/fixtures/codex-contract.generated.ts`, and `--check` compares that artifact exactly. Unit tests compare the provider fallback declarations and namespace ordering plus the supported Pi tool families and stock V2 spawn surface/output against it, while preserving Pi's documented non-reserved namespace. This does not prove the rest of the manually reviewed model-facing reference.

The optional live model-guidance eval covers explicit non-delegation, proactive parallelism, queue-only addressing, and sparse waiting:

pnpm --filter @clanker-stuff/subagents exec node scripts/evaluate-model-guidance.ts --dry-run
