# IT current-state

Existing tools, handoffs, and friction.

Group the actual current landscape by phase, department, or function. Label manual handoffs and formats (file, email, copy/paste) where evidenced. Distinguish pain points from neutral components and proposed changes; current-state diagrams should not silently include target-platform capabilities. The companion [integration view](type-dp-integration.md) can show the proposal using corresponding identifiers. Use containers for actual organizational boundaries, not arbitrary visual groups that imply ownership.

Geometry examples: [it-state](../assets/example-it-state.html). These retain an upstream illustration palette; use [design defaults](design.md) for new work.
