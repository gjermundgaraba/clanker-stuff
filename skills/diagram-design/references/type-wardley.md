# Wardley map

User needs, value-chain dependencies, and evolution.

Anchor the value chain in a user need. Vertical position indicates visibility to the user, not a numeric score. Horizontal bands are Genesis → Custom-built → Product → Commodity, representing evolution rather than generic maturity. Component positions express these judgments; do not move them merely to straighten links.

Use dependency lines between components, with separate arrows for proposed/expected evolution. Evolution arrows normally run toward commodity; any different movement needs an explicit interpretation. This is a strategy map, not runtime topology: protocols and request traffic belong in architecture. Qualify uncertain placements and forecasts rather than presenting qualitative axes as precise measurements.
