# User story map

Narrative activities and release scope.

Order backbone activities left to right by user narrative, with steps and stories under their activity. Vertical position represents priority or release slices, not workflow state. If the question concerns release scope, draw a labeled cut across the relevant slice; do not invent a release decision merely to fill the pattern. Keep gaps aligned to activity columns. Stories describe user outcomes, with identifiers and estimates retained where useful. Dependencies or enabling technical work may be annotated without pretending they are separate user activities.

Geometry examples: [story-map](../assets/example-story-map.html). These retain an upstream illustration palette; use [design defaults](design.md) for new work.
