# Nested containment

Scopes and boundaries.

Outer containers are broader scopes and inner containers belong to them. Sibling containers need not interact. Label each boundary and preserve its actual meaning (ownership, security scope, folder, configuration inheritance). Inclusion does not automatically imply permission inheritance or precedence; annotate those rules separately. Reserve header and inner padding so borders do not touch labels. Overlapping membership needs a set diagram or explicit cross-reference, not false single-parent nesting.
